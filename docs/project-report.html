1. Abstract

Traditional Know-Your-Customer (KYC) onboarding processes suffer from redundant verification cycles, single points of failure in centralized storage, and widespread exposure of personally identifiable information (PII). This project proposes and implements AegisID, a privacy-conscious, decentralized digital identity verification system.

Users submit mock identity documents through a web application. Administrators review the submission and issue digital credentials registered as cryptographic commitments on an Ethereum-compatible smart contract (IdentityVerification.sol). Third-party verifiers scan a QR code to inspect the authoritative validity status (ACTIVE, REVOKED, NOT FOUND) directly from the smart contract without accessing private personal data.

The system features cryptographic Sign-In with Ethereum (SIWE) wallet authentication, salted document commitments, automated on-chain receipt verification, live tamper-resistance proof checking, and authoritative on-chain revocation.

2. Introduction & Problem Statement

2.1 The Problem

In modern financial and regulatory services, identity verification is repeated for every institution. This presents three severe challenges:

  1. Excessive Data Exposure: Users repeatedly upload copies of national identity cards, passports, and utility bills, expanding the attack surface for identity theft.
  2. Centralized Vulnerabilities: Centralized credential registries represent single points of compromise for unauthorized credential issuance or silent revocation tampering.
  3. Static Credentials: Physical or paper-based credentials cannot be reliably revoked in real time without trusting an unverified intermediary.

2.2 Proposed Solution

AegisID introduces a decoupled architecture:

  • Private Off-Chain Storage: Mock documents and personal profiles are retained off-chain in protected storage with strict access controls.
  • On-Chain Privacy Commitment: The smart contract stores only an opaque 32-byte credential identifier and a salted document digest. Zero PII is committed to the blockchain.
  • Dynamic Locator QR: The QR code encodes only a verification URL pointing to the credential identifier. When scanned, verification queries live contract state on the blockchain, ensuring that revocation is authoritative and instantaneous.

3.1 Salted Commitment Scheme

To protect against rainbow-table and dictionary pre-image attacks on structured identity documents, the system uses a two-phase hashing scheme:

$$\text{FileDigest} = \text{SHA-256}(\text{DocumentBinary})$$ $$\text{Salt} \leftarrow \text{SecureRandom}(32\text{ bytes})$$ $$\text{Commitment} = \text{Keccak-256}(\text{FileDigest} \parallel \text{":"} \parallel \text{Salt})$$

Only $\text{Commitment}$ is recorded on-chain. The salt is preserved off-chain in the secure database. Document integrity can be proven at any time by recomputing the digest with the retained salt and comparing it against the smart contract record.

4. Smart Contract Specification

The smart contract IdentityVerification.sol inherits OpenZeppelin's established Ownable access-control primitives.

4.1 State Structure

struct Identity {
    address subject;
    address issuer;
    bytes32 documentCommitment;
    uint256 issuedAt;
    uint256 revokedAt;
    bool exists;
    bool revoked;
}

mapping(bytes32 => Identity) public identities;

4.2 Core Methods & Access Control

Function Visibility / Access Purpose
issueCredential(...) External, onlyOwner Registers a new credential commitment. Reverts on duplicate ID or zero address.
revokeCredential(...) External, onlyOwner Permanently revokes an active credential. Reverts on repeat revocation.
verifyCredential(...) External View, Public Returns (exists, active, subject, issuer, issuedAt, revokedAt) without gas fees.
getCredential(...) External View, Public Returns the full Identity struct for the given ID.

5. Security & Threat Analysis

Threat Vector Mitigation Strategy in AegisID
On-Chain PII Leakage Zero personal data (names, birthdates, raw document numbers) is committed to the EVM. Only salted cryptographic digests are stored, complying with GDPR Right-to-be-Forgotten requirements.
Unauthorized Issuance Contract-level onlyOwner access controls ensure only the deployer's cryptographic key can issue credentials, independent of frontend UI guards.
Static QR Tampering QR codes never embed a static status flag. They contain only a resource locator URL. The public verifier dynamically checks the smart contract in real time.
Wallet Replay / Impersonation SIWE challenge-response authentication issues single-use cryptographic nonces that expire in 5 minutes (WalletChallenge table).
Transaction Hash Spoofing The backend directly verifies transaction receipts against the blockchain provider, confirming status == 1, matching contract targets, and parsing event parameters.

6. Testing & Experimental Evaluation

The system was evaluated using two automated test suites covering 22 comprehensive test scenarios.

6.1 Smart Contract Unit Tests (Hardhat / Chai)

The smart contract test suite (IdentityVerification.test.js) validated 13 scenarios with 100% pass rate:

  • Deployer is assigned initial owner.
  • Authorized owner can issue valid credentials and emit CredentialIssued.
  • Non-owner unauthorized caller reverts with OwnableUnauthorizedAccount.
  • Rejection of zero-address subjects, empty IDs, and empty document commitments.
  • Rejection of duplicate credential IDs.
  • Authorized owner can revoke active credentials and emit CredentialRevoked.
  • Prevention of repeat revocation and non-existent credential revocation.
  • Public verification reports exists == false for unissued IDs.
Result: 13 of 13 contract unit tests passing (0.4s execution time).

6.2 Backend E2E Lifecycle Tests (Node.js Native Test Runner)

The integration suite (integration.test.js) executed the full end-to-end user-to-blockchain lifecycle:

  • User registration and bcrypt password hashing verification.
  • JWT issuance and role-based route guard enforcement.
  • Multipart synthetic document upload with storage isolation.
  • Admin review queue filtering, inspection, and approval.
  • Salted commitment preparation and public verification reporting NOT_FOUND.
  • Audit log persistence for issuance, revocation, and verification events.
Result: 9 of 9 integration test scenarios passing (0.6s execution time).

7. Limitations & Future Scope

  • Local EVM Environment: The current implementation runs on a local Hardhat node (Chain ID 31337). The architecture is ready for Ethereum Sepolia / Polygon testnet deployment.
  • Zero-Knowledge Proofs: Future versions can integrate zk-SNARKs (Circom / snarkjs) for selective attribute disclosure (e.g., proving citizenship or age ≥ 21 without revealing birthdate).
  • W3C Standard Alignment: Standardizing issued credentials into W3C Verifiable Credentials (VCs) and Decentralized Identifiers (DIDs).

8. Conclusion

AegisID demonstrates a functional, privacy-first digital identity verification framework. By marrying off-chain synthetic document inspection with on-chain cryptographic commitments and live QR verification, the system resolves the trade-off between user privacy and decentralized verifiable authenticity.
